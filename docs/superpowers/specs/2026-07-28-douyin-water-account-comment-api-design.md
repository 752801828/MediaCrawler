# 抖音水号评论接口优先与旧方式回退设计

## 目标

在保留现有抖音评论抓取方式的前提下，新增一条使用水号浏览器登录态的评论接口通道，并将其设为默认通道。

新通道需要：

1. 直接分页请求抖音一级评论与二级评论接口，不先依赖作品详情接口。
2. 使用任务规划分配的水号浏览器目录获取 Cookie、`msToken`、浏览器环境与实时签名。
3. 将接口响应映射为项目现有抖音评论表字段。
4. 普通作品和 Tag 作品继续分表保存。
5. 接口模式失败时自动回退到原项目评论抓取方式。
6. 保持现有飞书同步流程，不新增脱敏。

## 非目标

- 不删除或替换现有评论抓取实现。
- 不持久化 Cookie、Token、签名参数或完整认证请求 URL。
- 不修改评论表结构。
- 不把 Tag 评论写入普通评论表。
- 不承诺还原抖音接口已经脱敏或未返回的用户信息。

## 方案选择

采用独立的“水号接口评论抓取器”，由创作者运营任务层负责选择和回退。

未采用直接改写现有 `DouYinClient.get_aweme_all_comments()` 的方案，因为这会把新旧通道耦合在同一个方法中，难以记录实际使用的通道，也不利于单独回退。

未采用独立外部脚本方案，因为它会重复浏览器初始化、任务规划、数据库写入、Tag 分表与飞书同步逻辑。

## 运行模式

评论任务默认按照以下顺序执行：

1. 从当前任务的水号 profile 启动浏览器上下文。
2. 打开目标作品页面，使 Cookie、本地存储和签名环境与作品请求一致。
3. 创建水号接口客户端并验证登录态。
4. 直接抓取全部一级评论。
5. 对具有回复数量的一级评论抓取全部二级评论。
6. 每页抓取成功后立即通过现有评论存储回调写入数据库。
7. 接口通道完成后继续现有飞书同步。
8. 如果接口通道在重试后失败，记录错误类型并调用原项目评论抓取方式。

回退只针对当前作品。一个作品回退不应迫使同一任务中的其他作品全部使用旧方式。

## 接口与分页

一级评论接口：

`/aweme/v1/web/comment/list/`

主要参数：

- `aweme_id`
- `cursor`
- `count`
- `item_type`

二级评论接口：

`/aweme/v1/web/comment/list/reply/`

主要参数：

- `item_id`：作品 ID
- `comment_id`：一级评论 ID
- `cursor`
- `count`
- `item_type`

分页不设置业务页数和评论条数上限。以下任一条件成立时结束当前分页：

- `has_more` 为假。
- 接口返回空评论列表。
- 下一游标与已请求游标重复。

接口请求沿用项目现有合理间隔和有限重试，避免无间隔高频请求。重试过程中可以刷新作品页并重新读取 Cookie 和本地存储，但不得把认证信息打印到日志。

## 新旧通道边界

新接口通道负责：

- 读取水号登录态。
- 请求一级、二级评论接口。
- 验证响应结构和分页游标。
- 将原始评论对象交给统一映射与存储层。

旧通道继续保留当前项目的作品详情与评论抓取流程。

下列情况触发当前作品自动回退：

- 水号 profile 未登录。
- 响应为空、为 `blocked` 或返回平台风控错误。
- 请求在有限次数重试后仍超时或失败。
- 响应缺少必要分页结构。
- 游标或评论数据类型异常，无法安全继续。

如果新接口已经保存了部分页面后才失败，旧通道仍可继续执行。数据库按评论唯一键 upsert，因此已经保存的评论不会重复新增。

## 数据库路由

- 普通作品评论写入 `douyin_aweme_comment`。
- Tag 作品评论写入 `douyin_tag_aweme_comment`。
- Tag 评论仍使用“作品 ID + 评论 ID”作为唯一业务身份。
- 一级评论的 `parent_comment_id` 保存为空字符串。
- 二级评论的 `parent_comment_id` 保存其所属一级评论 ID。

两类表复用同一个接口响应映射函数，避免字段含义漂移。

## 字段映射

| 数据库字段 | 接口字段或来源 | 说明 |
| --- | --- | --- |
| `comment_id` | `cid` | 评论唯一 ID |
| `aweme_id` | `aweme_id`，缺失时使用当前任务作品 ID | 作品 ID |
| `content` | `text` | 评论文字 |
| `create_time` | `create_time` | 平台评论时间戳 |
| `sub_comment_count` | `reply_comment_total`，兼容 `reply_comment_count` | 一级评论回复总数 |
| `parent_comment_id` | 抓取二级评论时使用当前一级评论 ID | 一级评论为空 |
| `like_count` | `digg_count` | 缺失时保存 `0` |
| `pictures` | `image_list[].origin_url.url_list`，兼容其他可用图片地址 | 多个地址使用现有格式连接 |
| `user_id` | `user.uid` | 平台用户 ID |
| `sec_uid` | `user.sec_uid` | 平台 Sec UID |
| `short_user_id` | `user.short_id` | 用户短号 |
| `user_unique_id` | `user.unique_id` | 用户自定义抖音号 |
| `creator_hash` | 使用 `user.uid` 调用现有本地哈希函数 | 不是接口原始字段 |
| `nickname` | `user.nickname` | 不在项目侧脱敏 |
| `avatar` | `user.avatar_medium`，兼容其他头像对象 | 取首个可用地址 |
| `user_signature` | `user.signature` | 用户签名 |
| `ip_location` | `ip_label` | 评论 IP 归属地标签 |
| `add_ts` | 本地首次写入时间 | 由存储层生成 |
| `last_modify_ts` | 本次抓取时间 | 由映射层生成 |

## 无法保证获取的字段

以下字段虽然有映射，但接口不保证每条评论都返回：

- `short_user_id`：用户没有短号或平台裁剪时为空。
- `user_unique_id`：用户未设置自定义抖音号、注销或隐私限制时为空。
- `user_signature`：用户未填写或平台未下发时为空。
- `avatar`：账号异常、注销或头像对象缺失时为空。
- `ip_location`：旧评论、未展示归属地或平台未下发时为空。
- `pictures`：纯文字评论为空；平台可能只返回临时图片地址。
- `user_id`、`sec_uid`：极少数受保护、注销或异常账号可能为空。
- `nickname`：项目不主动脱敏，但平台响应已脱敏时无法还原。

`creator_hash`、`add_ts` 和 `last_modify_ts` 由本地生成，因此不属于接口可获取字段。

字段缺失时保存空值，不以伪造内容替代，也不因为单个可选字段缺失而丢弃整条评论。

## 日志与可观察性

每个作品至少记录：

- 作品 ID。
- 当前通道：`water-api` 或 `legacy`。
- 一级评论页码、请求游标、当页条数和累计条数。
- 二级评论所属一级评论 ID、请求游标、当页条数和累计条数。
- 水号接口重试次数。
- 是否发生自动回退及不含密钥的失败类型。
- 当前作品最终保存的一级、二级评论数量。

日志不得输出 Cookie、Token、签名参数、完整认证 URL 或完整请求头。

## 错误处理

- 单页请求失败采用有限次数重试和递增等待。
- 重试时刷新作品页并更新客户端 Cookie。
- 单个作品最终失败时记录作品 ID，不影响其他目标继续运行。
- 新接口和旧通道都失败时，任务结果应明确标记该作品失败。
- 数据库单条写入失败不得静默忽略，应记录评论 ID 与异常类型。
- 浏览器清理阶段的已关闭异常不得覆盖真实抓取结果。

## 飞书同步

评论仍先写入 MySQL，再沿用现有同步出站表和飞书字段映射。

- 普通评论继续同步到普通评论多维表。
- Tag 评论继续同步到 `tbl2YGN6CJszL4Ri`。
- 不新增昵称、用户 ID 或评论内容脱敏。
- 数据库为空的可选字段按现有空值规则同步。

## 验证

自动化测试需要覆盖：

1. 默认选择水号接口通道。
2. 一级评论多页抓取直到 `has_more=0`。
3. 二级评论多页抓取，并正确填写父评论 ID。
4. 重复游标可以安全停止。
5. 接口字段完整映射到现有评论表字段。
6. 一级评论父评论 ID 为空。
7. 图片字段能够兼容不同图片地址结构。
8. 普通评论与 Tag 评论分别写入正确表。
9. 水号接口失败后仅对当前作品调用旧通道。
10. 部分接口数据已写入后回退不会产生重复记录。
11. 平台缺失可选用户字段时仍保存评论。
12. 日志不包含 Cookie、Token 和签名值。

实际验证使用一个已知存在一级、二级评论的作品，核对：

- 接口报告评论总数与保存数量。
- 一级和二级评论分别保存成功。
- MySQL 字段值与接口响应一致。
- 普通评论与 Tag 评论不会串表。
- 飞书同步数量与本次应同步记录一致。
- 人工制造接口失败后能够看到明确的 `water-api -> legacy` 回退日志。
