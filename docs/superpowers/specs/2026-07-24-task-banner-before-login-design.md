# 登录前任务横幅设计

## 背景

创作者运营任务会按飞书计划依次调用抖音或小红书公开爬虫。如果已有登录状态失效，浏览器会显示二维码。当前二维码出现前缺少醒目的任务说明，操作者难以判断应该使用哪个平台、哪个账号扫码，存在扫错账号的风险。

## 目标

每个公开爬虫任务在初始化数据库、创建浏览器和显示二维码之前，输出一段醒目的任务横幅。横幅只用于识别当前任务，不暂停执行，也不要求人工确认。

## 非目标

- 不改变登录方式、二维码生成方式或登录状态判断。
- 不改变飞书计划、账号分配、抓取目标或抓取顺序。
- 不增加扫码前的 `Y/N` 确认。
- 不输出 Cookie、手机号、密码、Token、飞书密钥等敏感信息。
- 不修改普通 `main.py` 命令行启动流程；本次范围是创作者运营任务桥接入口。

## 方案

在 `creator_ops/crawler_bridge.py` 的 `run_public_task()` 统一入口生成并输出横幅。任务对象在该位置已经包含平台、任务类型、账号配置、目标和评论开关，同时浏览器尚未创建，因此可保证横幅早于二维码出现。

不在各平台的 `login.py` 中分别实现，避免重复代码；不只在总调度器中实现，避免直接调用 `run_public_task()` 时遗漏提示。

## 横幅内容

横幅使用明显的分隔线，并按固定顺序展示：

1. 平台中文名：抖音或小红书。
2. 任务类型：作品详情或创作者作品。
3. 账号类型：主账号、水号，或两者兼有。
4. 账号模板名称。
5. 解析后的账号目录绝对路径。
6. 目标数量。
7. 完整目标 ID 或链接列表，逐行编号。
8. 一级评论开关。
9. 二级评论开关。
10. 扫码提醒。

示例：

```text
============================================================
【即将执行任务】
平台：抖音
任务：作品详情 + 评论
账号类型：水号
账号模板：dy_text_data_dir
账号目录：D:\browser_data\dy_text_data_dir
目标数量：2
目标：
  1. 7518846965308820762
  2. 7496135103426481408
一级评论：开启
二级评论：关闭
提示：如出现二维码，请使用与上述账号目录对应的账号扫码
============================================================
```

## 输出时机与数据流

`run_public_task()` 接收任务后：

1. 将任务类型转换为公开爬虫的 `crawler_type`。
2. 解析账号模板的绝对路径。
3. 进入任务级配置作用域。
4. 输出任务横幅并立即刷新输出。
5. 初始化数据库。
6. 创建并启动浏览器爬虫。
7. 如登录失效，由现有平台登录模块显示二维码。

横幅不会阻塞步骤 5–7。即使登录状态有效、不显示二维码，也仍会输出横幅，方便确认当前任务。

## 组件边界

新增一个只负责格式化任务信息的内部函数，以及一个负责输出横幅的内部函数。格式化函数不读取网络、数据库或浏览器状态；输出函数使用项目现有日志系统并确保及时刷新。

平台名称、任务名称、账号类型和开关状态在格式化层转换为中文。二级评论状态读取任务作用域中实际使用的 `config.ENABLE_GET_SUB_COMMENTS`。

## 错误处理

- 空目标列表仍显示 `目标数量：0`，不影响现有任务错误处理。
- 账号路径仅展示已由 `Settings.profile_path()` 验证并解析的路径。
- 横幅格式化失败不得静默跳过；测试应保证所有现有任务类型均可格式化。
- 长目标列表完整逐行显示，不截断，以免操作者误判当前任务范围。

## 测试

在 `tests/creator_ops/test_crawler_bridge.py` 增加测试：

- 抖音作品详情任务显示平台、账号目录、所有目标、一级和二级评论状态。
- 小红书创作者任务显示正确的平台、任务类型和账号类型。
- 横幅输出发生在 `init_db()` 和 `crawler_factory()` 之前。
- 横幅不包含 Cookie、Token、密码等配置内容。
- 登录状态有效或失效不改变横幅输出行为。

## 验收标准

- 每个创作者运营公开爬虫任务启动时，终端首先出现完整醒目的任务横幅。
- 二维码出现时，操作者能够从横幅明确判断平台、账号目录和抓取目标。
- 不需要额外输入，现有任务继续自动执行。
- 现有测试和新增测试全部通过。
