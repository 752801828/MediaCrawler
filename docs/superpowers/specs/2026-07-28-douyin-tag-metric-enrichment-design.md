# 抖音 Tag 指标补全与作者过滤设计

## 目标

抖音 Tag 列表接口未提供有效的作者粉丝数和作品播放数，当前 MySQL 中对应字段为空，飞书数字字段将空值显示为 `0`。本次改动需要：

1. 使用水号现有 Cookie 和请求签名机制补全作者粉丝数。
2. 公开端无法取得真实播放数时保存为空，不再把接口占位值 `0` 当成真实播放量。
3. 作者 `1719260615816915` 的 Tag 作品不得写入 MySQL 或飞书多维表。
4. 单条详情请求失败时，不能中断整个 Tag 抓取任务。

## 数据来源

- Tag 列表继续使用 `/aweme/v1/web/challenge/aweme/`，负责分页发现作品。
- 作者详情复用现有 `DouYinClient.get_user_info()`，请求 `/aweme/v1/web/user/profile/other/`，用于补全 `follower_count`、`following_count` 和 `total_favorited`。
- 所有请求复用当前水号浏览器上下文生成的 Cookie、请求头、签名参数和限速配置，不读取附件中的固定 Cookie。

实际接口验证显示：`/aweme/v1/web/aweme/detail/` 与附件参考的 `/aweme/v1/web/aweme/post/` 均请求成功，但他人作品的 `statistics.play_count` 固定返回 `0`。这是公开端的数据限制，不能用点赞数等其他指标替代。

## 抓取流程

每页 Tag 作品按以下顺序处理：

1. 从列表响应解析 `author.uid`、`author_user_id` 和 `author.sec_uid`。
2. 若作者 ID 为 `1719260615816915`，立即跳过，不调用补充接口、不写数据库。
3. 按 `sec_uid` 请求作者详情；同一任务内每个作者只请求一次，并缓存解析后的作者统计。
4. 合并列表与作者详情后，调用现有 Tag Repository 批量 upsert。
5. 补充请求失败时记录不含 Cookie 的警告日志，并保存列表接口仍然能够提供的基础字段。

为避免风控，补充请求保持低并发并沿用现有抓取间隔。作者缓存仅存在于当前爬虫任务内，不持久化 Cookie 或响应凭证。

## 合并规则

- 列表接口已有的有效值保留。
- `play_count` 仅保留公开接口返回的有效非零值；缺失或占位 `0` 统一保存为 `NULL`，飞书写为空。
- 作者详情负责补全 `author_follower_count`、`author_following_count`、`author_total_favorited`、作者昵称及认证字段。
- 详情响应缺少某字段时保持为空，不伪造 `0`。
- 原始 Tag 列表响应仍保存在 `raw_aweme_json`，不把 Cookie、请求头或签名参数写入数据库。

## 作者过滤

过滤常量为作者 ID `1719260615816915`，采用双层保护：

1. 抓取层在详情请求和 Repository upsert 之前过滤，保证新数据不进入 MySQL。
2. 同步层读取 Tag 作品数据时再次过滤，保证历史或人工导入的数据不进入飞书。

Tag 评论目标列表由已保存的 Tag 作品生成，因此被排除作者的作品不会进入 Tag 评论抓取，也不会进入 Tag 评论飞书表。

当前数据库已由用户清空，当前飞书 Tag 作品表中未发现该作者记录，所以本次不执行历史数据删除。

## 错误处理与日志

- 作者详情返回风控、空响应、超时或字段结构异常时，记录 `sec_uid` 和错误类型。
- 日志不得输出 Cookie、Token、完整请求 URL 查询参数或响应中的认证字段。
- 单条补全失败只影响该条补全字段；Tag 分页、数据库保存和后续评论抓取继续执行。
- 作者详情失败结果在当前任务内也缓存，避免针对同一作者持续重复失败请求。

## 验证

自动测试覆盖：

1. 公开接口的播放数占位 `0` 保存为 `NULL`。
2. 作者详情能够补全空的粉丝数，并且同一作者只请求一次。
3. 已有有效值不会被空值或 `0` 覆盖。
4. 补充接口失败时仍保存基础 Tag 数据。
5. 作者 `1719260615816915` 不进入 Repository，且同步查询再次排除。
6. 其他作者的 MySQL 和飞书字段映射保持不变。

实际验证使用一个 Tag 任务，检查 MySQL 与飞书中的粉丝数来自作者详情，公开播放数为空，并确认排除作者在两端的记录数为 `0`。
