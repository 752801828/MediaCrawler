# 小红书与抖音二级评论抓取设计

## 背景

当前项目使用全局配置 `ENABLE_GET_SUB_COMMENTS` 控制二级评论抓取。直接将它设为 `True` 会同时影响所有支持二级评论的平台，无法满足“只为小红书和抖音开启”的要求。

本次改动需要让小红书和抖音在所有启动方式下保持一致：飞书运营任务与直接运行 `main.py` 都应遵循相同的平台级规则。

## 目标

- 小红书和抖音在一级评论抓取开启时抓取二级评论。
- 其他平台继续保持二级评论关闭。
- 二级评论写入现有评论表，通过父评论字段关联一级评论。
- 分页异常不能造成无限循环。
- 任务开始前的横幅和运行日志明确显示二级评论状态及当前目标。
- 不修改或删除已有评论数据，不新增评论表。

## 非目标

- 不为飞书计划表新增二级评论配置字段。
- 不改变其他平台的一级评论抓取行为。
- 不承诺抓取数量与网页展示总数完全相等；平台隐藏、删除、审核中或接口不可见的评论仍可能无法获得。
- 不绕过平台访问控制或风控。

## 方案选择

### 采用：平台白名单

增加统一的二级评论启用判断，以平台白名单限定为 `xhs` 和 `dy`。爬虫核心、客户端和运营任务桥接层都使用该判断，避免启动方式不同导致行为不一致。

优点：

- 范围精确，不会误开其他平台。
- 配置语义清晰，后续新增平台时可显式加入。
- 所有入口行为一致。

### 不采用：直接开启全局布尔值

改动最少，但会同时开启其他平台，超出确认范围。

### 不采用：仅在运营任务桥接层临时开启

可以满足飞书任务，但直接运行 `main.py` 时行为不同，容易造成误判和漏抓。

## 架构与配置

保留现有总开关，并增加平台级允许列表及统一判断函数。二级评论最终启用条件为：

1. 一级评论抓取已开启；
2. 二级评论总开关已开启；
3. 当前平台位于二级评论平台白名单中。

默认配置将总开关设为开启，白名单仅包含：

- `xhs`
- `dy`

其他平台即使包含二级评论实现，也因不在白名单中而保持关闭。

运营任务的配置作用域需要保存、设置并恢复二级评论相关配置，防止连续执行不同平台任务时状态泄漏。任务横幅使用同一个统一判断函数显示实际状态。

## 数据流

### 抖音

1. 获取作品的一级评论页。
2. 保存该页一级评论。
3. 对 `reply_comment_total > 0` 的一级评论调用二级评论接口。
4. 分页保存二级评论，二级评论记录携带父评论 ID。
5. 当前一级评论的二级评论完成后，再处理下一个一级评论。

### 小红书

1. 获取笔记的一级评论页。
2. 保存一级评论，以及一级评论响应中已携带的首批二级评论。
3. 当 `sub_comment_has_more` 为真时，使用根评论 ID 和游标继续请求。
4. 分页保存剩余二级评论，记录父评论关系。
5. 当前根评论完成后继续下一条。

现有数据库表和存储回调继续复用，不进行破坏性迁移。

## 分页与错误处理

两个平台的一级和二级评论分页都必须：

- 记录已经请求过的游标；
- 游标重复时记录警告并结束当前分页；
- 返回空评论页时结束当前分页；
- 平台明确返回 `has_more = false` 时正常结束；
- 单个根评论发生可恢复的数据获取错误时记录目标和根评论 ID，继续处理后续根评论；
- 登录失效、账号受限等全局错误继续向上抛出，不能伪装为抓取完成。

抓取日志至少包含平台、作品或笔记 ID、根评论 ID、页游标和本页获得的评论数，便于定位少抓发生在哪一层。

## 数据一致性

- 二级评论沿用平台评论 ID 作为幂等更新依据，重复运行不应产生重复记录。
- `parent_comment_id` 必须保存根评论 ID。
- 一级评论响应内嵌的二级评论与后续分页结果可能重复，存储层应依靠评论 ID 更新或忽略重复记录。
- 旧记录保持原样；本次启用只新增或更新本次接口返回的数据。

## 测试

单元测试覆盖：

- 小红书和抖音的平台判断返回开启；
- 其他平台的平台判断返回关闭；
- 一级评论关闭时二级评论联动关闭；
- 运营任务配置作用域退出后恢复原配置；
- 抖音二级评论正常分页、空页和重复游标；
- 小红书二级评论正常分页、空页和重复游标；
- 回调获得二级评论并保留父评论关系；
- 任务横幅显示实际二级评论状态。

回归测试运行项目现有测试套件。随后使用当前飞书计划中的抖音作品进行一次实际抓取，核对新增二级评论数量和 `parent_comment_id`；如存在小红书已启用评论任务，也用同样方式验证。

## 验收标准

- 小红书和抖音任务横幅显示“二级评论：开启”。
- 两个平台的二级评论接口被调用，数据库出现带父评论 ID 的记录。
- 其他平台二级评论仍为关闭。
- 空页或重复游标不会导致任务卡住。
- 现有测试及新增测试通过。
- 改动仅提交并推送到用户 fork 的当前分支，不推送到上游项目。
