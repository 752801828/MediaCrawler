# 抖音水号评论接口优先实施计划

## 目标

按已确认设计实现水号评论接口优先模式，保留现有评论抓取方式作为按作品自动回退通道，并复用普通评论与 Tag 评论的数据库和飞书同步链路。

## 任务一：统一评论字段映射

修改 `store/douyin/__init__.py`：

- 提取可单独测试的评论映射函数。
- 作品 ID 缺失时使用当前任务作品 ID。
- 一级评论的父评论 ID 标准化为空。
- 二级评论允许使用接口抓取器显式传入的一级评论 ID。
- 图片地址兼容 `origin_url`、`medium_url` 与 `download_url`。
- 保持昵称、用户 ID 和评论内容原值，不新增脱敏。

新增测试覆盖完整字段、缺失可选字段、一级父评论为空、二级父评论和单地址图片。

## 任务二：新增水号接口评论抓取器

新增 `media_platform/douyin/comment_api.py`：

- 接收现有 `DouYinClient`、浏览器上下文、页面和存储回调。
- 打开目标作品页面并更新 Cookie。
- 直接分页调用一级评论和二级评论接口。
- 不限制页数，以 `has_more`、空列表和重复游标结束。
- 二级评论写入前附加所属一级评论 ID。
- 每页打印作品、级别、游标、当页数量和累计数量。
- 有限重试时刷新页面并更新 Cookie。
- 日志不得输出 Cookie、Token、签名值和完整认证 URL。

新增单元测试覆盖全量分页、二级评论、重复游标、重试和异常响应。

## 任务三：接入爬虫并保留旧通道

修改 `media_platform/douyin/core.py`：

- `batch_get_note_comments()` 根据配置选择接口优先或旧方式。
- 接口优先模式逐作品执行，避免多个作品共享同一个签名页面。
- 某个作品接口抓取失败后，仅该作品调用现有 `get_comments()`。
- 普通评论和 Tag 评论继续使用同一个存储回调与上下文分表标记。
- 日志明确显示 `water-api`、`legacy` 和自动回退。

新增测试覆盖默认接口选择、按作品回退和其他作品继续执行。

## 任务四：配置与任务展示

修改 `config/base_config.py` 与 `creator_ops/crawler_bridge.py`：

- 增加评论通道配置，项目通用默认值保留旧方式。
- 创作者运营中的抖音水号评论任务临时设为 `water_api`。
- 将配置加入作用域恢复列表，任务结束后恢复原值。
- 抖音评论任务横幅显示“水号接口优先，失败回退旧方式”。

扩展 `tests/creator_ops/test_crawler_bridge.py`，验证作用域恢复、任务实际模式和横幅。

## 任务五：验证

运行：

- 新增评论接口测试。
- 抖音分页测试。
- 抖音存储映射测试。
- 创作者运营 crawler bridge 测试。
- 与 Tag 评论存储相关的现有测试。

完成后检查：

- `git diff --check`
- 工作区只包含本次计划、实现和测试。
- 不包含 `.env`、Cookie、Token、签名或临时抓取输出。
- 普通评论与 Tag 评论表路由没有改变。
